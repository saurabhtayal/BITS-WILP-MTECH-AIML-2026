PART 1

The building blocks

Before clues and answers: what a vector is, what a matrix is, and why your data is already one.

A vector is a list of numbers. That's it.

One number can't describe much. "The flat costs 28" — but how big is it? How many bedrooms? So you answer with a short list instead, kept in a fixed order. That list is a vector.

The one rule. Fix the order once and never change it. From then on slot 3 means the third thing — in every vector you write for that problem.

Three things worth fixing right now.  ① The dimension is just how many slots — nothing to do with how big the numbers are.  ② Two vectors are equal only if every slot matches, so (3,2) ≠ (2,3).  ③ There is a zero vector — all slots 0 — and adding it changes nothing.

Two moves, and only two: add and scale

Everything in this entire subject is built from exactly two operations. Both are things you already do without thinking.

Add — Ravi buys (2 rice, 1 dal, 3 milk), Meera buys (1, 2, 0). Together the kitchen got (3, 3, 3). Rice with rice, dal with dal. Slot by slot.
Scale — a recipe for 4 people is (2, 1, 3). Cooking for 8? Double everything: (4, 2, 6). One number multiplies every slot.

see it as a walk

With two slots you can draw a vector: (3, 1) means "3 steps right, 1 step up". Adding = walk one, then the other. Scaling = same road, different distance.

Closure — the quiet superpower. Add two lists of three numbers and you get a list of three numbers. Scale one and you still get a list of three numbers. You can never escape. A set with that guarantee is called a vector space, and it is the floor everything else stands on.
Try to break it: can you add (1, 2, 3) to (4, 5)? No — there is no third number for the 3 to pair with. "Shapes do not match" is the most common error message in all of data science, and it starts right here.

Stack the lists and you get a matrix

One student's marks is a vector. Write the whole class down — one student per line, subjects always in the same order — and you have built a table. Mathematics calls that a matrix: m rows tall, n columns wide.

Tap any number below to see how it is addressed.

Tap a cell.
Row first, column second — always. a23 is row 2, column 3. It is never the other way round, in any book or any library. Same habit as a flat's address: the floor, then the flat on that floor.
And vectors are matrices too. A single column of m numbers is an m × 1 matrix; a single row of n numbers is 1 × n. So a vector isn't a new species — it's a very thin matrix, and every rule below applies to both.

Surprise: a photograph is a matrix

A black-and-white picture is a grid of tiny squares, and each square holds one number saying how dark it is. That grid is a matrix — nobody had to convert anything.

Draw on the left (tap or drag). The numbers on the right are what the computer actually stores.

Scale it up. A colour photo from your phone is three of these stacked — one grid for red, one for green, one for blue — each about twelve million numbers. When people say image processing is "just linear algebra", they mean it literally.

What people actually mean by "data"

The word gets thrown around loosely. Here it means one very simple thing — and the only real difficulty is that every textbook uses different words for the same three parts.

Matrices hold numbers only. So "Delhi", "yes" and "14 March" have to be converted first. Choose below and watch the row that actually reaches the model:

Never number your categories 1, 2, 3. Writing Delhi = 1, Mumbai = 2, Pune = 3 in one column would claim Pune is three times Delhi and Mumbai sits halfway between them. Neither means anything. Cities have no order, so each gets its own 0/1 column — that's called one-hot encoding, because exactly one is hot per row. Sizes small/medium/large do have an order, so there 1/2/3 is fine.

Why all of this exists: Xw

Here is the pay-off, and it is the sentence the whole page is heading towards. Your data is a matrix X. The thing a model must learn is a vector of weights w — how much each column matters. And the model's guess for every single row at once is one multiplication: Xw.

PART 2

The puzzle

What counts as a clue, a real factory story, and the three possible endings.

What you just did, in official words

Each lamp was a linear equation: a clue where the hidden numbers are only multiplied by known numbers and added up. Making all lamps green at once means solving the system. You found x=3, y=2 — the one dial setting both clues accept.

What keeps a clue "linear"? The hidden numbers stay gentle — no squaring them, no multiplying them together:

✓ 3x + 2y = 7 ✓ x − 4y + z = 0 ✗ x2 + y = 7 ✗ x·y = 3
Why care? In machine learning, every row of a dataset is one linear clue about a model's hidden weights. Solving clues = fitting models. Same game, bigger dials.

The three possible endings

Every system of linear clues ends one of exactly three ways. Never two answers. Never five. Watch it happen with the slides' own example.

Start with two fixed clues about three hidden numbers:

x1 + x2 + x3 = 3 x1 − x2 + 2x3 = 2

Here's the secret: add these two clues together. The x2 parts cancel (+1 and −1), leaving a forced fact the pair quietly guarantees:

2x1 + 3x3 = 5  (forced — no choice about it)

Now you write clue 3. It has the shape 2x1 + 3x3 = c. Drag c:

When the answers are endless, you get a free dial

With the echo clue, one hidden number becomes your choice. Pick x3 — the other two lock in automatically (x1 = 2.5 − 1.5x3 and x2 = 0.5 + 0.5x3). Every position of this dial is a full, genuine solution:

Name to remember: the locked numbers are pivot variables; the free one is a free variable. Part 5 shows how to spot them instantly. And why never exactly 2 answers? Two working dial settings always let you slide smoothly between them, and everything in between works too — so 2 instantly becomes infinity.

Three hidden numbers? Clues become walls

With three unknowns, one clue like x1 + x2 + x3 = 3 is kept green by a whole flat sheet of points — a wall floating in space (the official word: a plane). Two walls that aren't parallel meet along a line, like a wall meeting the floor. Then the third wall decides the ending.

PART 4

The toolbox

To solve big systems we need better notation. Meet the matrix — and the five moves you can do with it.

A matrix is a packed table

Look at the factory table again. The words around it are decoration — the information is the grid of numbers. Strip the labels, keep the grid, add brackets: that's a matrix. Press the button and watch the packing happen.

Grammar of the grid: a matrix with m rows and n columns is "m×n" (rows first, always). The cell in row i, column j is called aij — click any cell above (after packing) to read its address. Thin special cases: one row = a row vector; one column = a column vector. So vectors are just skinny matrices, and a plain list of numbers like our dial settings (2, 3, 1) is a vector too.

Vectors have a superpower called closure: add two of them, or stretch one by a number, and you get another vector — you never leave the club. A club like that is called a vector space. Even polynomials join: adding (2+x) + (1+3x) = 3+4x is exactly adding the lists (2,1)+(1,3)=(3,4). Same move, different costume.

Easy moves: add cell-by-cell, scale every cell

Adding matrices and scaling matrices work exactly as you'd hope. Same-shaped grids add matching cells; a number λ (lambda) multiplies every cell. Hover the result to see each cell's two parents; drag λ to scale live.

3
ML in one line: a training update is literally new weights = old weights + (−η) × gradient — one matrix add, one matrix scale, repeated millions of times.

The big move: multiply — a row dances with a column

This is the one operation that is not cell-by-cell, and it runs all of modern ML. To fill one cell of C = A·B: take a row of A and a column of B, multiply them pair by pair, add it all up. Like a bill: quantities × prices, summed.

shapes must shake hands

The dance only works if the row of A and the column of B have the same length. A is m×k and B is k×n → the inner numbers must match, and the answer is m×n:

Order matters! Even when both exist, A·B ≠ B·A — press "flip the order" above and compare the finished grids. Matrix land has no "swap freely" rule.

Rules that survive (audit them yourself)

Three comfy rules from ordinary arithmetic still hold — and one breaks. Don't take my word for it: roll random matrices and check with real numbers.

The do-nothing matrix I (ones on the diagonal, zeros elsewhere) plays the role of the number 1 — multiplying by it changes nothing. Remember it: it stars in Part 4's finale.

The undo button — and how it breaks

A square matrix A transforms lists of numbers. Its inverse A−1 is the matrix that undoes it: apply A, then A−1, and you're back where you started. Watch it on a crowd of points — then break it.

That bottom number, a11a22 − a12a21, is the determinant, det A — the gatekeeper. Dividing by zero is forbidden, so: the undo button exists exactly when det ≠ 0. And the broken preset shows why, not just that: a zero-det matrix squashes different points onto the same spot. Once two points overlap, no machine on earth can tell them apart again. Information lost = no undo. (Official name for such a matrix: singular.)

Two rules to file away (slide 25): undoing a chain reverses it, (AB)−1 = B−1A−1 — socks on then shoes on; undo = shoes off first. And there's no shortcut for sums: (A+B)−1 is not A−1+B−1.

The flip (transpose)

One last tool, thirty seconds. The transpose AT flips a matrix over its diagonal — rows become columns, so a 2×3 grid becomes 3×2. Press flip. That's genuinely all it is.

Rules: flipping twice returns A. Flips spread over sums. And on a product the order reverses — (A·B)ᵀ = Bᵀ·Aᵀ, socks & shoes again. Press audit to verify with numbers.
ML sightings: similarity scores in attention are Q·KT, and backpropagation sends signals backwards through a layer using WT. The flip is everywhere.

Three moves that never change the answer

For messy systems we clean first, solve second. Only three edits are answer-safe: swap two clues (order is decoration), scale a clue by any number except 0 (both sides together — same information, louder voice), and add one clue to another (if both hold, their sum holds; subtract to undo). To edit fast, drop the letters and keep numbers: [A | b], the augmented matrix, with the demands after the bar.

The deluxe staircase (RREF) — answers by eye

Keep cleaning past the staircase: make every pivot a 1, and clear above pivots too, so each pivot sits alone in its column. That's reduced row-echelon form. Why bother? Because free columns then spell out their own silent moves. Slide 54's matrix, already deluxe (solving Ax = 0):

The grand finale: the inverse, computed by cleaning

Remember Part 4's undo button? For big matrices, forget formulas — elimination builds it. Park the do-nothing matrix I on the right as a flight recorder: it starts as "nothing done yet" and absorbs every move you make. Clean the left half all the way to I, and the recorder ends up holding everything that turns A into I — which is precisely A−1.

Why it works: column i of A−1 solves the mini-system "Ax = column i of I". Parking all of I on the right solves all those systems in one sweep. If the left half ever stalls (a zero pivot, nothing to swap in), then det A = 0 — the broken undo button from Part 3, met again. Working engineers' proverb: solve, don't invert — libraries run this sweep instead of building formulas.
PART 6

The payoff

Where this lands in machine learning, a final boss quiz, and the one card to keep.

The doorway to ML

Real datasets hand you thousands of clues for a handful of dials — systems so overloaded that the honest ending is almost always 0. No exact solution. And that's where machine learning begins: linear regression (next lecture) finds the dial setting that makes every lamp as close to green as possible. Least total complaint. Every tool from today — columns as steps, staircases, the undo button, the flip — is a working part inside that machine.

So today wasn't just algebra. It was the grammar of the entire course.

🗂 The one card to keep

  1. Pack it: write the clues as [A | b].
  2. Clean it: sweep to a staircase using only swap · scale-by-nonzero · add.
  3. Read the fate: a row "0 = non-zero" → 0 answers. Otherwise: no free columns → 1; free columns → ∞.
  4. One landing: free dials to 0, walk the staircase bottom-up.
  5. Silent moves: one per free column (that dial 1, others 0, demands 0).
  6. Everything: answers = landing + any mix of silent moves.
  7. Bonus: clean [A | I] until the left is I — the right half becomes A−1.
